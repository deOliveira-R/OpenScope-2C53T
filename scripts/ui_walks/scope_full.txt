# scope_full.txt -- every key of the scope screen, in every view, for scripts/ui_walk.py
#
#   name | command ; command ; wait <seconds>
#
# The scope's base screen (firmware/src/ui/scope_screen.c, ARCH-1 B7): each key
# is one property set, a procedure request, or UI state (the arrow stage, the
# active channel, the Oscilloscope Settings page). The walk presses every key
# (short and long) in the Y-T view in each arrow stage, with the cursors, with
# a mask, and in the roll, X-Y, FFT, split and waterfall views, and reads back
# what each must have changed.
#
# It runs unchanged on the image before B7 (fd20895) and on the B7 image: it
# uses only what both have (`ui seq`, `get`, `set`, `wait`, and `mask teach` /
# `mask clear` to make and drop a mask: no key can make the first one). So it
# never sets view.run and never reads a property B7 added (view.cursel,
# view.curv1.., trig.code, trig.held, mask.state / hold / pending); cursor
# moves and the spectrum views' keys are judged from the screenshots. Run it
# on both images with --shots and compare, step by step: the `ui screen`
# line, the `get` answers, the pictures, the redraw rates.
#
# ui_walk.py records the `ui screen` line after every step and the answer of
# every `get`; what each must show is on the "# expect" line above the step.
# Unless a line says otherwise, both images answer the same.
#
#   `ui screen` on the scope:  screen=scope instrument=scope overlay=none stack=scope
#     focus=zoom|chmove|trigmove|cursor|mask   ach=CH1|CH2   run=run|stop
#     view=yt|roll|xy|fft|split|waterfall      lcdforeign=0 throughout
#
# Redraw counters (`ui dump`: scope_full, scope_live, redraw_all):
#   - a step that only waits: 0 scope_full and 0 redraw_all per second in every
#     view (the views are composed per column, never blanked);
#   - a key that changes a value or shows a popup: one redraw_all, on both images;
#   - a cursor move: no redraw_all (one live frame);
#   - a direct `set` (the steps named *_set*): before B7 one redraw_all each;
#     with B7 none for a value the live frame and the bars repaint (ranges,
#     positions, timebase, trigger), one scope_full and no redraw_all for a
#     layout change (cursor mode, a channel on / off, math, persistence), one
#     redraw_all for another view (view.mode, tb.roll).
#
# Bench signal: 100 kHz, 0..3.3 V square on CH1; CH2 open. The walk changes
# saved settings and puts them back at the end. Coupling changes click a relay.
# Autoset, 50 % centre and the baseline request land where the signal puts
# them: the same on both images, not a fixed value. The last steps (long AUTO,
# baseline calibration, from Y-T and from roll) are expected to be REFUSED with
# the signal connected; they only touch RAM corrections: reboot the unit after
# the walk. AUTO and long AUTO in roll (f16_roll_*, f19_*) are the two places
# where the images may differ by design of the change: see there.
# POWER cannot be sent from the shell: hold it by hand on the plot, the
# countdown must appear over it and a release must repaint the scope.
